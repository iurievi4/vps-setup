# NaïveProxy Manager (v1.0.0-MODULAR)

Модульная система развёртывания и управления высокопроизводительным прокси-сервером **NaïveProxy** с **Caddy (:443 TLS-ALPN-01)**, встроенным сайтом-заглушкой **Nginx (:80)** и веб-панелью администрирования **Web UI**.

---

## 1. Архитектура: Два независимых продукта

Репозиторий `vps-setup` содержит две независимые версии:

```text
vps-setup/
│
├── naiveproxy-install.sh      # СТАРЫЙ All-in-One монолит (v2.9-STABLE) — эталон, не изменяется
│
└── naiveproxy-manager/        # НОВЫЙ модульный менеджер (v1.0.0-MODULAR)
    │
    ├── naiveproxy-manager.sh  # Главный скрипт-оркестратор и меню
    │
    ├── modules/               # Функциональные модули
    │   ├── common.sh          # Константы, пути, логирование, системные и сетевые проверки
    │   ├── nginx.sh           # Nginx :80: неразрушающее обнаружение сайтов и сайт-заглушка
    │   ├── caddy.sh           # Caddy :443: компиляция xcaddy, Caddyfile, транзакции, сервис
    │   ├── naiveproxy.sh      # Движок: Go, пользователи users.json, клиенты, мастер доменов
    │   ├── webui.sh           # Web UI: защищённый Python-сервер, sudoers, helper
    │   └── maintenance.sh     # Обслуживание: статус, резервное копирование, обновления, удаление
    │
    └── README.md              # Документация архитектуры и руководство пользователя
```

### Преимущества модульного разделения
- **Изоляция сбоев**: Изменение логики одного компонента (например, Nginx или Web UI) не затрагивает другие.
- **Чистый оркестратор**: `naiveproxy-manager.sh` не содержит монолитного кода — только меню и вызовы модулей.
- **Транзакционность Caddy**: Изменения `Caddyfile` всегда проверяются через `caddy validate` во временном файле до применения.
- **Безопасность Nginx**: Существующие сайты пользователя на порту 80 гарантированно сохраняются и не затираются.
- **Стабильный эталон**: Монолит `naiveproxy-install.sh` остаётся полностью рабочим запасным вариантом.

## 2. Назначение модулей

| Модуль | Описание и ответственность |
| :--- | :--- |
| `common.sh` | Цвета, пути (`/etc/naiveproxy`, `/etc/caddy`), логирование (`info`, `success`, `warn`, `error`), валидация email и доменов, определение внешнего IPv4/IPv6, проверка занятости портов, проверка сертификатов X.509. |
| `nginx.sh` | Проверка порта 80, обнаружение существующих сайтов (`CUSTOM`, `DEFAULT`, `STUB`), установка Nginx при отсутствии, безопасное создание изолированной заглушки `naiveproxy-stub` без удаления файлов пользователя. |
| `caddy.sh` | Проверка порта 443, компиляция Caddy с модулем `forwardproxy@naive` через `xcaddy`, автоматическое создание 2 ГБ Swap при нехватке RAM, валидация `Caddyfile`, создание systemd-службы `caddy.service`, транзакционный откат при сбоях. |
| `naiveproxy.sh` | Установка Go (Golang), многопользовательская база `users.json`, генерация клиентских конфигураций `client.json` и ссылок для NekoBox/Matsuri/Sing-box, мастер проверки домена и DNS-диагностика (A, AAAA, CAA). |
| `webui.sh` | Встроенная веб-панель управления на Python 3 (`127.0.0.1:18080`), доступная по защищённому HTTPS через Caddy (`/admin/`), генерация защищённого хелпера `/usr/local/bin/naiveproxy-helper` для операций добавления/удаления клиентов через sudo. |
| `maintenance.sh` | Вывод реквизитов подключения, комплексная диагностика (read-only), резервное копирование и восстановление конфигураций (`/var/backups/naiveproxy`), безопасное обновление Caddy, полное удаление с восстановлением системы. |

## 3. Быстрый старт

### Требования к серверу
- **ОС**: Ubuntu 20.04 / 22.04 / 24.04 LTS или Debian 11 / 12
- **Архитектура**: x86_64 (amd64) или ARM64 (aarch64)
- **Права**: `root`
- **Порты**: TCP 80 (Nginx) и TCP 443 (Caddy)

### Запуск менеджера

```bash
cd /root/vps-setup/naiveproxy-manager
chmod +x naiveproxy-manager.sh modules/*.sh
./naiveproxy-manager.sh
```

## 5. Команды командной строки (CLI)

Менеджер поддерживает прямой вызов любой подсистемы без интерактивного меню:

```bash
# Диагностика и проверка статуса
./naiveproxy-manager.sh status

# Просмотр реквизитов и client.json
./naiveproxy-manager.sh config

# Управление клиентами
./naiveproxy-manager.sh clients
./naiveproxy-manager.sh client-list
./naiveproxy-manager.sh client-add user_alice password123 "Телефон Алисы"
./naiveproxy-manager.sh client-del user_alice

# Управление службами
./naiveproxy-manager.sh restart
./naiveproxy-manager.sh web-restart

# Резервное копирование конфигураций
./naiveproxy-manager.sh backup
./naiveproxy-manager.sh restore

# Безопасное обновление Caddy
./naiveproxy-manager.sh update
```

## 6. Безопасность и архитектурные решения

1. **Неразрушающий Nginx**: Скрипт анализирует `/etc/nginx/sites-enabled/`. Если обнаружен пользовательский сайт, он остаётся активным. При отсутствии сайтов создаётся изолированная заглушка `naiveproxy-stub`, а стандартный дефолтный файл отключается без удаления.
2. **Транзакционный Caddyfile**: Изменения конфигурации Caddy записываются во временный файл и валидируются (`caddy validate`) до перезагрузки. В случае ошибки служба Caddy не прерывает работу.
3. **Безопасный Web UI**: Панель слушает только локальный сокет `127.0.0.1:18080`. Доступ осуществляется исключительно через обратный прокси Caddy с шифрованием TLS и HTTP Basic Auth на эндпоинте `/admin/`.
4. **Служба `naiveproxy-helper`**: Добавление и удаление клиентов из веб-интерфейса выполняется выделенным хелпером через sudo с захватом `PAYLOAD="$(cat)"` и строгой валидацией JSON.
