Единый модульный инструментарий для комплексного администрирования Linux VPS: первичная инициализация системы, многоуровневое усиление безопасности (*hardening*), блокировка паразитных сканеров через **VPS IP Guard**, развёртывание высокоскоростного прокси NaïveProxy, подключение маскировочных веб-сайтов Nginx, управление медиа-сервером TorrServer, независимое администрирование **Microsoft SQL Server** и автоматизированное шифрованное резервное копирование.

Центральной точкой входа и главным оркестратором проекта является интерактивное меню `vps-manager.sh` (также доступно через `vps.sh` и `install.sh`).

## Многоуровневая модель безопасности (Defense-in-Depth)

Фильтрация сетевого трафика организована по принципу эшелонированной обороны:

```text
Входящий пакет из сети Интернет
         │
         ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ЭШЕЛОН 1: VPS IP Guard (Ядро Linux: iptables + ipset)                  │
│                                                                        │
│   Цепочка: INPUT -> VPS-IP-GUARD                                       │
│   Проверка наборов hash:net:                                           │
│     ├── VPS-IP-GUARD-V4 (Gov, Scanner, Skipa, Manual) ──► [ DROP ⛔ ]  │
│     └── VPS-IP-GUARD-V6 (IPv6 сети при наличии)        ──► [ DROP ⛔ ]  │
│                                                                        │
│   * Атомарный swap через временные наборы                              │
│   * ExecStop исключён: остановка сервиса не снимает фаервол            │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ (Очищенный трафик)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ЭШЕЛОН 2: Межсетевой экран UFW (Stateful Firewall)                     │
│                                                                        │
│   Политика по умолчанию: DEFAULT DROP INCOMING                         │
│   Разрешены только строго необходимые порты:                           │
│     ├── SSH (кастомный порт/tcp)                                       │
│     ├── HTTP / ACME Challenge (80/tcp)                                 │
│     ├── HTTPS / NaïveProxy / Xray (443/tcp)                            │
│     ├── TorrServer (8090/tcp или кастомный)                            │
│     ├── MS SQL Server (1433/tcp только доверенным сетям)               │
│     └── Панель 3x-ui (кастомный порт/tcp)                               │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ЭШЕЛОН 3: Интеллектуальный анализ Fail2ban                             │
│                                                                        │
│   Динамический мониторинг журналов:                                    │
│     ├── jail sshd     : 3 попытки -> бан на 24 часа                    │
│     ├── jail recidive : повторные атаки -> бан на 1 неделю             │
│     └── jail 3x-ipl   : защита веб-панели управления                   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ ЭШЕЛОН 4: Целевые службы (Nginx, Caddy, Xray, MSSQL, TorrServer)       │
│   - Маскировочные веб-сайты (Nginx Decoy)                              │
│   - Шифрованный транспорт Chromium (NaïveProxy)                        │
│   - Изолированные базы данных и учетные записи (accs.db, 0600)         │
└────────────────────────────────────────────────────────────────────────┘
```

## Модули и компоненты системы

### 1. Базовая настройка VPS

- **Обновление пакетов:** актуализация системы через `apt update && apt upgrade` с подавлением интерактивных зависаний (`needrestart`).
- **Файл подкачки (Swap):** генерация swap 2 GB с параметром ядра `vm.swappiness=10`, предотвращающим падения служб по OOM (*Out Of Memory*).
- **Сетевой тюнинг (TCP BBR):** автоматическая проверка поддержки BBR ядром Linux, включение очереди `fq` и алгоритма `bbr` для минимизации задержек и потерь пакетов.
- **Кастомный порт SSH:** безопасная смена порта SSH с предварительным открытием правил в UFW и защитой от потери доступа (*lockout protection*).
- **Cloudflare WARP:** развертывание официального клиента `cloudflare-warp` в изолированном режиме локального SOCKS5-прокси (`127.0.0.1:40000`).

---

### 2. Безопасность и VPS IP Guard

Автономный модуль сетевой фильтрации ядра `/usr/local/sbin/ip-guard`:
- **Ядро на базе `ipset` и `iptables`:** входящий трафик фильтруется через наборы `hash:net` (`VPS-IP-GUARD-V4` и `VPS-IP-GUARD-V6`).
- **Официальные источники списков:** правительственные сети, сканеры уязвимостей, хостинг-провайдеры и ботнеты.
- **Безопасный systemd unit:** в службе `vps-ip-guard.service` отсутствует `ExecStop` — остановка сервиса не снимает защиту ядра.
- **Атомарный swap:** обновление списков происходит через временный ipset без обрыва текущих соединений.
- **Ручной чёрный список:** быстрое добавление и снятие блокировок (`ip-guard ban` / `ip-guard unban`).

---

### 3. Прокси-сервер NaïveProxy & Caddy

- **Сетевой стек Chromium:** трафик NaïveProxy маскируется под обычный защищённый HTTP/2 или HTTP/3 трафик браузера Google Chrome.
- **Модульная структура (`modules/`):** автоматическая сборка Caddy с плагином `forwardproxy`, генерация `Caddyfile`, создание пользователей и экспорт клиентских конфигураций.

---

### 4. Сайты-заглушки и камуфляж Nginx

Защита от активного зондирования сетевыми цензорами. Менеджер `nginx-templates.sh` развёртывает сайты-камуфляжи на порту 80/443:
- **Speedtest:** страница HTML5-замера скорости сети.
- **Games Site:** портал с браузерными мини-играми.
- **Converter / Convertit:** сервисы конвертации единиц измерения и файлов.
- **Filecloud / Downloader:** камуфляж под облачное хранилище данных.
- **YouTube endless captcha:** страница имитации капчи в стиле YouTube.

---

### 5. Медиа-сервер TorrServer Manager (`torrserver-manager.sh`)

Автономный менеджер сервиса потокового воспроизведения торрентов:
- **Двойное автообнаружение:** автоматическое определение как нативной службы systemd, так и контейнера в Docker (с диагностикой конфликта портов).
- **Безопасная авторизация HTTP Basic Auth:** хранение логинов и паролей в файле `accs.db` с правами `chmod 600` (пароли не раскрываются в командной строке `ps aux`).
- **Сетевые настройки:** смена порта, выбор адреса прослушивания (`0.0.0.0` или `127.0.0.1`), согласование с фаерволом UFW.
- **Обновление с автооткатом:** загрузка официальных бинарников с GitHub, ELF-валидация и автоматический возврат к рабочей копии при ошибке запуска.
- **Резервное копирование:** создание полных архивов `.tar.gz` и пошаговое восстановление.

---

### 6. Администрирование СУБД: MSSQL Manager (`mssql-manager.sh`)

Полнофункциональный модульный менеджер для администрирования Microsoft SQL Server (SQL Server 2022 Express, используемый системой ЛЭРС УЧЁТ, и корпоративных экземпляров):

#### Поддерживаемые режимы работы:
1. **Docker-контейнер (`mssql_server`):** управление контейнером, томами данных, проброшенными портами, трансляция путей бэкапов.
2. **Нативная служба systemd (`mssql-server`):** управление системной службой, статусом, автозапуском и журналами `journalctl`.
3. **Удалённый SQL Server (Remote TCP):** администрирование баз данных, пользователей и резервных копий на внешних серверах без вмешательства в удалённую ОС.

#### Модульная структура (`modules/mssql/`):
* `common.sh` — цвета терминала, безопасный ввод, трехуровневое подтверждение опасных операций (`confirm_action`), SQL-движок `run_sql_query` с маскировкой паролей от `ps aux`.
* `detect.sh` — автообнаружение Docker, службы systemd, утилит `sqlcmd` и сокетов порта 1433.
* `connections.sh` — управление профилями подключений в `/etc/mssql-manager/connections/` с правами `chmod 600`.
* `docker.sh` — управление контейнером SQL Server (`start`, `stop`, `restart`, `logs`, инспекция томов).
* `native.sh` — управление службой `mssql-server` через `systemctl`.
* `databases.sh` — список баз данных, размеры, файлы `.mdf`/`.ldf`, создание БД, защищённое удаление.
* `users.sh` — серверные логины, пользователи БД, роли (`sysadmin`), смена паролей.
* `backup.sh` — резервное копирование баз в `.bak`, выгрузка на хост в `/var/backups/mssql-manager/`, проверка `RESTORE VERIFYONLY`, очистка устаревших копий.
* `restore.sh` — восстановление из `.bak`, анализ `HEADERONLY`/`FILELISTONLY`, перемещение файлов (`MOVE`), защищённая перезапись существующих баз (`REPLACE`).
* `security.sh` — экспресс-аудит безопасности: статус `sa`, режим смешанной аутентификации, проверка `xp_cmdshell`.
* `network.sh` — мониторинг сокетов :1433, интерактивное добавление/удаление правил в UFW.
* `maintenance.sh` — регламентное обслуживание: `DBCC CHECKDB`, обновление статистики `sp_updatestats`, мониторинг блокировок процессов.
* `performance.sh` — мониторинг оперативной памяти (`max server memory`), ресурсоёмкие CPU-запросы, статистика буферного пула.
* `diagnostics.sh` — формирование структурированных отчётов (без секретов) в `/var/log/mssql-manager/`, просмотр ErrorLog.
* `config.sh` — настройка путей хранения резервных копий и фиксация прав доступа (`0700`/`0600`).

#### Трёхуровневая модель безопасности MSSQL:
* **Уровень 1 (Безопасно):** чтение списков, аналитика, логи — выполняется без лишних запросов.
* **Уровень 2 (Изменение):** перезапуск, создание БД, смена пароля — интерактивное подтверждение `[y/N]`.
* **Уровень 3 (Разрушительные операции):** удаление базы (`DROP DATABASE`) и восстановление с перезаписью (`RESTORE WITH REPLACE`):
  * Системные базы (`master`, `model`, `msdb`, `tempdb`) защищены от удаления.
  * Обязательное создание страховочной копии текущей базы перед изменением.
  * Требуется подтверждение вводом точного имени целевой базы данных.

### 7. Система диспетчеризации ЛЭРС УЧЁТ (`lers-manager.sh`)

Специализированный инструмент для управления платформой учёта энергоресурсов ЛЭРС УЧЁТ:
- Управление службами опроса, веб-интерфейсом и сервером ЛЭРС.
- Настройка внешних подключений к базе данных SQL Server (в Docker или нативном сервере).
- Управление доменными именами, привязками портов и SSL-сертификатами.

---

### 8. Резервное копирование и шифрование баз

- **`export-xui-db.sh`:** создание зашифрованных AES-256-CBC архивов баз SQLite для панелей 3X-UI / X-UI с автоматической проверкой целостности.
- **Интерактивное восстановление:** интеграция в `setup.sh` для быстрого развёртывания клиентских настроек из резервных копий.

## Настройка клиентских приложений NaïveProxy

Формат строки подключения, генерируемой скриптом:
```text
naive+https://USERNAME:PASSWORD@YOUR_DOMAIN:443
```

- **v2rayN (Windows):** меню *Серверы* → *Импортировать ссылку* или ручное создание сервера типа *NaïveProxy* с указанием пути к `naive.exe`.
- **Nekoray / Matsuri (Windows, Android):** добавление профиля типа *Naïve*, указание домена, порта 443 и учётных данных.
- **Sing-box / Clash Meta (Mihomo):** стандартный outbound-блок типа `naive` с указанием сервера, порта 443 и реквизитов авторизации.

## Диагностика и команды проверки

### Проверка безопасности и IP Guard:
```bash
ip-guard status                           # Статус службы и правил фильтрации
ipset list VPS-IP-GUARD-V4 -terse         # Загруженные в ядро сети ipset
iptables -L VPS-IP-GUARD -n -v            # Цепочка фильтрации iptables
systemctl list-timers vps-ip-guard-update.timer --no-pager
```

### Быстрые команды MSSQL Manager:
```bash
sudo ./mssql-manager.sh status            # Проверка статуса активного экземпляра
sudo ./mssql-manager.sh list-dbs          # Вывод списка всех баз данных
sudo ./mssql-manager.sh backup LERS       # Резервное копирование базы LERS в .bak
```

### Проверка служб и веб-серверов:
```bash
systemctl status caddy --no-pager         # Служба Caddy (NaïveProxy)
systemctl status nginx --no-pager         # Веб-сервер Nginx
systemctl status torrserver --no-pager    # Служба TorrServer
docker ps                                 # Запущенные контейнеры (mssql_server и др.)
ss -tulpn | grep -E ':(80|443|1433|8090|40000)' # Активные слушающие порты
```
